## Key Implementation Details

### 1. Auth Guard
`isAuthorized()` checks `Authorization: Bearer {CRON_SECRET}` header OR `?secret=` query param. Returns 401 immediately if invalid.

### 2. Dedup Strategy
`tryInsertExecution()` does `INSERT INTO cron_executions (date, action, status)`. If the unique constraint on `(date, action)` is violated, it returns "duplicate" and the handler skips. The `?force=true` query param bypasses this check.

### 3. Orchestration Flow
`fetch notes → summarizeNotes → sendDailyReminder → update status`. Each step errors independently. On summarization failure, a fallback message with raw notes is sent instead.

### 4. Cron Schedule
`vercel.json` defines `0 0 * * 1-5` UTC. At midnight UTC, the WIB date computation correctly identifies "yesterday" as the WIB date at that moment.

## Decisions Made

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Dedup | DB unique index | Survives cold starts, no extra infra |
| Auth | Bearer + query param | Bearer for cron, ?secret= for manual curl testing |
| Fallback | Raw notes on failure | Better than silence -- user gets something |
